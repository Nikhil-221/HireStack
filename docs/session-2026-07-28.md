## 6. Auth hardening

Clarified scope with the user before making changes. Delivered:

- `POST /auth/register` (new) — replaces `/users/create_user`, which was removed.
- `require_recruiter` dependency — Job Management endpoints now 403 for any non-admin/recruiter account.
- Frontend **Register page** (`/register`) with a link from Login; redirects to Login with a success banner.

Explicitly deferred (by user's choice, not oversight): no duplicate-email validation (still a raw 500 on conflict), no `is_active` check at login, no refresh tokens (flat 60-minute expiry).

Later refined: since Admin and Recruiter are the same concept in this project, `/auth/register`'s `role` field was narrowed from `Literal["admin", "recruiter"]` to `Literal["recruiter"]` only. Existing `role="admin"` accounts still work for login/access — the guard still treats both as equivalent — this only closed off *creating new* admin accounts through the API. The frontend Role field was kept as a single-item dropdown rather than removed.

## 7. Bugs found and fixed along the way

- **CORS mismatch**: the frontend dev server happened to start on port 5174 (5173 was occupied), and the backend only whitelisted 5173 — every API call silently failed as cross-origin. Fixed by adding 5174 to `allow_origins`.
- **Windows port/process gotchas**: `uvicorn --reload` and `npm run dev` (Vite) each spawn a child process; killing the shell wrapper's PID does not stop the actual process underneath, which caused a couple of "port already in use" / stale-process incidents during testing. Resolved via `Get-NetTCPConnection -LocalPort <port> | Get-Process` to find the real PID.
